## E. 검증한 내용

- 로컬 모드 E2E(Playwright, Chromium): 로그인 리다이렉트 → 회원가입(관리자 이메일) → 상품 35종 렌더 → 검색 → 기록 팝업 저장 → 지표·내역·잔존 카페인·"내 최근 결제" 반영 → 2건째 기록 시 경고 문구 → 직접 추가 팝업 → 설정(목표 변경 즉시 반영) → 관리자 대시보드·상품·사용자 탭 → 모바일(400px) 4개 페이지 가로 스크롤 없음 → 모바일 팝업. 콘솔 오류 없음.
- Supabase 스키마: 로컬 PostgreSQL 16 에 auth 스키마를 흉내 내어 `schema.sql`(2회 실행, 멱등) · `seed.sql`(2회, upsert) 실행 성공. RLS 검증: 일반 사용자는 승인 상품 35종 + 본인 pending 만 조회, 직접 추가 시 pending 으로 강제, 본인 role 변경 차단, 타인 명의 기록 insert 거부, 상품 삭제·승인 상품 수정 무효, 비활성 사용자 insert 거부, anon 접근 거부, 관리자는 전체 프로필·기록 조회 및 승인/역할 변경 가능.
- 추가 E2E: 일반 사용자의 직접 추가 → "저장하고 기록" 연속 팝업 → 승인 대기 배지 → 관리자 페이지 접근 차단 → 관리자 로그인 후 승인 대기 승인 → 상품 수정(brand_key 유지, 확인일 기록) → 사용자 비활성화.
- 코드 리뷰(Supabase 경로 정독)에서 찾은 3건 수정: 가입 시 하루 목표 값 범위 초과로 DB 트리거가 실패할 수 있던 문제(클라이언트·SQL 양쪽 클램프), PostgREST timestamptz 표기 차이로 날짜 필터가 어긋날 수 있던 문제(UTC ISO 로 정규화 + 숫자 비교), 관리자 수정 시 brand_key 가 바뀌어 "스타벅스 N" 집계가 틀어지던 문제.
- CDN 자원(Pretendard 글꼴, supabase-js v2 UMD) 접근 확인.

## G2. `schema.sql` 을 두 번 실행하면 실패하던 문제

- `drop trigger ... on auth.users` 는 **테이블 소유권**이 필요합니다. SQL Editor 는 파일 전체를 한 트랜잭션으로 실행하므로, 이 한 줄이 실패하면 **그 뒤 전부가 롤백**됩니다(정책 0개). → 트리거가 없을 때만 만들고, 권한이 없으면 NOTICE 만 남기는 `do $$ ... exception ...` 블록으로 교체.
- 가입 시 트리거가 `raw_user_meta_data.daily_limit_mg` 를 검사 없이 숫자로 캐스팅 → 숫자가 아니면 `auth.users` INSERT 까지 롤백되어 가입 자체가 "Database error saving new user" 로 실패. → 정규식 검사 후 캐스팅.
- 이메일 없는 가입(전화·일부 OAuth)은 `lower(null)` 이 not null 제약에 걸려 가입 실패. → 프로필을 만들지 않고 넘어감.
- 스키마 적용 **전에** 가입한 사용자를 위한 프로필 backfill 추가(8번 절).
- `seed.sql` 재실행이 `status`·`source` 를 되돌리지 않아, 관리자가 시드 상품을 '반려' 하면 영원히 숨겨진 채로 남던 문제 수정. (관리자가 눌러 둔 확인일은 그대로 보존)
