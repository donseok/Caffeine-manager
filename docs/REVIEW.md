# 배포 전 검토 — 수정·확인 항목

작성일 2026-09-12 · 대상: 첫 공개 배포(GitHub Pages + Supabase)

## A. 배포 전에 반드시 할 것 (안 하면 동작이 달라짐)

| # | 항목 | 왜 필요한가 | 어디서 |
|---|---|---|---|
| A1 | `js/config.js` 에 `SUPABASE_URL` · `SUPABASE_ANON_KEY` 입력 | 비어 있으면 배포된 사이트가 **로컬 모드**로 돌아가 방문자마다 자기 브라우저에만 저장되고 계정도 공유되지 않음 | Supabase → Project Settings → API |
| A2 | `supabase/schema.sql` 실행 후 `supabase/seed.sql` 실행 | 테이블·보안 정책·가입 트리거·시드 상품 생성. 순서가 바뀌면 seed 가 실패함 | Supabase → SQL Editor |
| A3 | Auth URL 설정: Site URL / Redirect URLs 에 `https://<아이디>.github.io/caffeine-manager/` 등록 | 이메일 확인·비밀번호 재설정 링크가 돌아올 주소 | Supabase → Authentication → URL Configuration |
| A4 | "Confirm email" 켤지 결정 | 켜면 가입 후 메일 링크를 눌러야 로그인 가능(앱이 안내 문구를 띄움). 테스트 중엔 끄는 게 편함 | Supabase → Authentication → Providers → Email |
| A5 | GitHub 저장소 Settings → Pages → Source = **GitHub Actions** | 이걸 안 고르면 워크플로가 돌아도 사이트가 안 뜸 | GitHub |
| A6 | 관리자 이메일 확인 — 현재 `donseok75@gmail.com` (`js/config.js` 의 `ADMIN_EMAILS`, `schema.sql` 의 `admin_emails`) | 이 이메일로 가입해야 슈퍼관리자가 됨. 다른 이메일을 쓰면 두 곳 모두 수정 | 코드 · SQL |

## B. 데이터 정확성 — 배포 전 또는 직후 확인 권장

| # | 항목 | 내용 |
|---|---|---|
| B1 | **시드 상품 35종의 수치는 재확인 전** | 브랜드 공식 영양정보·제품 표시사항을 기준으로 입력했지만 최신 공식 페이지와 대조하지 않았습니다. 그래서 모든 시드 상품에 "확인 필요" 배지가 붙습니다. 관리자 화면 → 상품 관리에서 값을 대조하고 "확인✓" 를 누르면 확인일이 기록되고 배지가 사라집니다. |
| B2 | 특히 불확실한 항목 | 자바 칩 프라푸치노(340 kcal 로 입력, 시안에는 400), 카라멜 프라푸치노, 오늘의 커피(260 mg), 딸기 아사이 리프레셔(40 mg), 몬스터 에너지 국내 355 mL 캔(100 mg · 40 g · 155 kcal), 레드불 국내판(62.5 mg), 코카콜라(34 mg), 박카스D/F 당류·열량 |
| B3 | 가격은 모두 "확인 필요" | 기준가는 2025년 무렵 매장가 기준이라 현재와 다를 수 있음. 가격 확인일을 입력하면 카드에 "MM-DD 확인" 으로 표시됨 |
| B4 | 시안의 "총 204종 · 스타벅스 194" 는 예시 수치 | 실제 카탈로그는 35종으로 시작. 상품은 관리자 화면에서 추가하거나 `data/products.seed.json` 을 늘려 `python3 tools/gen-seed.py` 로 재생성 |

## C. 시안과 다르게 구현한 점 (의도적)

| # | 항목 | 이유 · 대안 |
|---|---|---|
| C1 | 상품 타일의 브랜드 이미지 슬롯 → **브랜드 첫 글자** 표시 | 로고 이미지 자산이 없음. 관리자 화면에서 상품별 `이미지 URL` 을 넣으면 그 이미지가 표시됨. 브랜드 단위 일괄 적용은 추후 `brands` 테이블로 확장 가능 |
| C2 | 1차 시안(1a·1b) 삭제 | 요청대로 2a·2b 만 구현. 원본 시안 파일은 저장소에 포함하지 않음 |
| C3 | 팝업을 iframe 모달로 구현 (`record.html` 별도 파일) | 파일은 분리하되 2b 시안과 같은 모습 유지. 주소창에 직접 열어도 단독 페이지로 동작 |
| C4 | 헤더 "이 기기에 저장" 칩 | Supabase 키가 있으면 "클라우드 저장" 으로 자동 전환 |
| C5 | 정렬 기본값 | 검색어가 없을 때 분류(커피→티→블렌디드→리프레셔→에너지→기타) → 브랜드 → 이름 순 |

## D. 알아 두어야 할 한계 (지금은 괜찮지만 공개 서비스라면 보완)

| # | 항목 | 설명 · 권장 |
|---|---|---|
| D1 | **비밀번호 찾기 없음** | Supabase `resetPasswordForEmail` + 재설정 페이지 추가 필요. 공개 서비스라면 배포 전에 넣는 것을 권장 (다음 작업 후보 1순위) |
| D2 | 사용자 삭제 불가 (비활성화만) | 클라이언트 anon 키로는 auth 사용자를 지울 수 없음. 삭제는 Supabase 대시보드 → Authentication → Users 에서 |
| D3 | 누구나 가입 가능 | 공개 URL 이므로 링크만 알면 가입됨. 제한하려면 Supabase → Authentication → "Allow new users to sign up" 끄고 초대 방식으로 |
| D4 | 무료 티어 메일 발송 한도 | Supabase 기본 SMTP 는 시간당 몇 통 수준. 가입자가 늘면 Custom SMTP(예: Resend) 설정 |
| D5 | 로컬 모드의 비밀번호 저장 | 브라우저 SHA-256 해시로 저장 — 개발·데모용이며 보안 기능이 아님. 클라우드 모드에서는 Supabase Auth 가 처리 |
| D6 | 분류 6종 고정 | 커피·티·블렌디드·리프레셔·에너지음료·기타. 늘리려면 `store.js` 의 `CM.CATEGORIES`, `schema.sql` 의 check 제약, CSS `.cat-*` 를 함께 수정 |
| D7 | 관리자 대시보드의 "최근 기록" 은 최근 20건만 | 전체 통계·기간별 집계는 추후 SQL 뷰로 확장 |
| D8 | 시간대 | 모든 날짜 계산은 접속한 브라우저의 로컬 시간 기준(한국 사용자면 KST) |

## E. 검증한 내용

- 로컬 모드 E2E(Playwright, Chromium): 로그인 리다이렉트 → 회원가입(관리자 이메일) → 상품 35종 렌더 → 검색 → 기록 팝업 저장 → 지표·내역·잔존 카페인·"내 최근 결제" 반영 → 2건째 기록 시 경고 문구 → 직접 추가 팝업 → 설정(목표 변경 즉시 반영) → 관리자 대시보드·상품·사용자 탭 → 모바일(400px) 4개 페이지 가로 스크롤 없음 → 모바일 팝업. 콘솔 오류 없음.
- Supabase 스키마: 로컬 PostgreSQL 16 에 auth 스키마를 흉내 내어 `schema.sql`(2회 실행, 멱등) · `seed.sql`(2회, upsert) 실행 성공. RLS 검증: 일반 사용자는 승인 상품 35종 + 본인 pending 만 조회, 직접 추가 시 pending 으로 강제, 본인 role 변경 차단, 타인 명의 기록 insert 거부, 상품 삭제·승인 상품 수정 무효, 비활성 사용자 insert 거부, anon 접근 거부, 관리자는 전체 프로필·기록 조회 및 승인/역할 변경 가능.
- CDN 자원(Pretendard 글꼴, supabase-js v2 UMD) 접근 확인.
